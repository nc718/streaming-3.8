# Kav AI Streaming

שרת WebSocket עצמאי לסטרימינג חי מול **טכנוליין / TLIVR** ו־**Gemini Live**.
הפרויקט אינו משנה את הפרויקט הקיים בתיקיית השורש.

## נקודת חיבור

- WebSocket: `wss://<הדומיין-שלך>/voice`
- בדיקה HTTP: `/`
- בדיקת בריאות: `/health`

בממשק הטכנוליין יש ליצור ערוץ סטרימינג ולהגדיר את נקודת הקצה ל־`wss://<הדומיין-שלך>/voice`.
אם הוגדר סוד בערוץ, הגדר אותו גם כ־`STREAM_SECRET` בשרת. החיבור חייב לשלוח:

```text
Authorization: Bearer <STREAM_SECRET>
```

## פורמט אודיו

- טכנוליין אל השרת: PCM16 little-endian, mono, 8000 Hz.
- השרת שולח ל־Gemini בתוך `realtimeInput.mediaChunks`: PCM16, mono, 16000 Hz.
- Gemini אל השרת: אודיו 24000 Hz בדרך כלל.
- השרת משדר לטכנוליין: PCM16, mono, 8000 Hz, בקצב טלפוני של כ־320 בייט כל 20 מ״ש כדי להימנע משליחה מהירה מדי ו־backpressure.

## הפעלה מקומית

```powershell
cd streaming
npm install
Copy-Item .env.example .env
# מלאו GEMINI_API_KEY ו-STREAM_SECRET
node server.js
```

להפעלת wss מקומי צריך reverse proxy ו־TLS.

## משתני סביבה

| משתנה | חובה | תיאור |
|---|---|---|
| `GEMINI_API_KEY` | כן | מפתח Google Gemini |
| `STREAM_SECRET` | מומלץ | סוד Bearer של ערוץ הטכנוליין |
| `GEMINI_LIVE_MODEL` | לא | מודל Gemini Live Audio |
| `GEMINI_VOICE` | לא | קול Gemini, למשל Kore או Charon |
| `SYSTEM_INSTRUCTION` | לא | הנחיית המערכת למודל |
| `BARGE_IN_RMS` | לא | סף עוצמת קול לעצירת השמעת הבוט כשמתחילים לדבר; ברירת מחדל `800` |
| `BARGE_IN_FRAMES` | לא | פריימי דיבור רצופים לפני שליחת `clear`; ברירת מחדל `3` |

## אירועים

כשחיבור Gemini מוכן, השרת מבקש ממנו לפתוח את השיחה בקול: **„שלום, איך אוכל לעזור לך היום?”**
אודיו מהמתקשר נשלח ל־Gemini כל עוד חיבור ה־AI מוכן.

השרת מקבל:

- `start` — מאתחל סשן Gemini Live ומגדיר את פרטי השיחה.
- פריימים בינאריים — אודיו המתקשר.
- `dtmf` — שולח בקשה טקסטואלית למודל (DTMF אינו נתמך כרגע במרכזייה המצויה לפי המדריך).
- `hangup` — סוגר את סשן Gemini וסוגר את הסוקט.

השרת יכול לשלוח לטכנוליין:

- פריימים בינאריים — אודיו Gemini.
- `clear` — barge-in.

השרת שולח `clear` כש־Gemini מזהה קטיעה או כשהשרת מזהה דיבור מעל סף העוצמה בזמן השמעת הבוט. האודיו מועבר ל־Gemini כשהחיבור מוכן, והאודיו שיוצא מהמודל מקוצב ל־320 בייט כל 20 מ״ש לפני שליחתו לטכנוליין. תור האודיו מוגבל ל־30 שניות; אם הוא מתמלא, השרת מנקה את האודיו הממתין, מפסיק לשלוח את המשך התשובה הנוכחית ומשאיר את השיחה פתוחה. כשהמודל מסיים את התור, השליחה מתחדשת בתשובה הבאה. בסיום השמעה נרשמים ללוג שיא התור וגודל נתוני WebSocket שעדיין ממתינים לשליחה.

לצורך אבחון נרשמים גם פריימי אודיו נכנסים (הראשון ואז כל 250 פריימים) ותחילת/סיום יצירת אודיו מ־Gemini. תוכן הדיבור עצמו אינו נרשם.

ניתוב סופי יכול להתבצע על ידי שליחה ידנית מהקוד:

```json
{"type":"transfer_extension","target":"/2"}
```

```json
{"type":"transfer_phone","target":"03XXXXXXX"}
```

```json
{"type":"transfer_queue","target":"<queue-id>"}
```

```json
{"type":"hangup"}
```

לפני פקודה סופית יש לסיים קודם משפט סיום ולהמשיך לשלוח את האודיו שלו, ואז לשלוח את הפקודה תוך עד 6 שניות ניקוז.
